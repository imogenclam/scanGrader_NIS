# REST API и примеры вызовов

Версия контракта 0.2.0 для КТ-2 от 24 ноября 2026 года. Алина Лисянская отвечает за аккаунты и проверки доступа, а Артур Галимов ведёт Classroom и оценивание. Операции, схемы JSON, формы файлов и статусы ответов описаны в [OpenAPI](../../api/openapi.yaml).

## Исполняемый пример

Соберите интерфейс и сервер по [README](../../README.md#сборка-из-исходников). На Linux и macOS следующая команда запускает проверку из корня проекта. На Windows замените `./scangrader` путём к `bin/ScanGrader.exe`.

```sh
node tests/contract/classroom.mjs ./scangrader
```

Скрипт создаёт временную SQLite и запускает сервер на свободном порту. Преподаватель публикует задание с эталоном. Студент вступает в предмет и отправляет два разных PDF одновременно. Скрипт проверяет, что обе квитанции указывают на одну сдачу и что преподавателю доступен первый принятый файл. Попытка получить эталон из студенческого аккаунта даёт HTTP 403. Если преподаватель завысит балл, сервер вернёт HTTP 400. После утверждения допустимой оценки скрипт проверяет итог в аккаунте студента. При расхождении с ожидаемым результатом процесс завершается с ошибкой. [Исходник вызовов](../../tests/contract/classroom.mjs)

## Примеры запросов и ответов

**Создание предмета.** После входа пользователь передаёт выданную сервером cookie `sg_session`. Преподаватель отправляет JSON методом `POST /api/subjects`.

```json
{"title":"Арифметика","description":"Вычисления и оценка ответа"}
```

Пример ответа с HTTP 201. Конкретный ID и код приглашения формирует сервер.

```json
{"id":4,"invite_code":"AB2CD3"}
```

**Публикация.** Преподаватель отправляет в `POST /api/subjects/4/assignments` форму `multipart/form-data`. Поля `title` и `statement` содержат название и текст задания. В `tasks` передаётся строка JSON `[{"number":1,"max":1}]`, в `reference` прикладывается UTF-8-файл `.tex` размером до 256 КиБ. Ответ 201 содержит `id` задания и `reference_version` с SHA-256 файла. Номера от 1 до 1000 уникальны, задач от 1 до 100. Максимум задачи строго положителен и не превышает 10 000.

**Сдача.** Для вступления в предмет студент передаёт код в `POST /api/subjects/join`. Затем он прикладывает PDF к полю `file` формы `POST /api/assignments/{id}/submissions`. Допускается до пяти страниц и 20 МиБ. При первой сдаче сервер возвращает HTTP 201, ID и `already_submitted: false`. При повторной отправке ответ имеет код 200 и тот же ID, а `already_submitted` принимает значение `true`. Код 400 означает, что PDF нечитаем или превышен предел страниц. Для слишком большого файла предусмотрен код 413. Повреждённое или пустое изображение страницы даёт 422. Если обработчик временно занят, возможен ответ 503.

**Утверждение.** Преподаватель видит `draft` или `manual` в `GET /api/submissions/{id}`. Для каждой задачи он передаёт номер, балл и непустой комментарий методом `POST /api/submissions/{id}/approve`.

```json
{"grades":[{"number":1,"score":0.5,"comment":"Способ выбран верно. Ошибка в последнем сложении."}]}
```

Успешный ответ имеет код 200 и тело `{"state":"approved"}`. Балл 2 при максимуме 1 даёт HTTP 400 с полем `error`. Повторное утверждение возвращает 409. В собственной сдаче до утверждения студент видит `waiting`, после получения результата видит `approved` и массив `final`.

## Аккаунты и граница доступа

- Код регистрации и код сброса состоят из шести цифр, действуют 15 минут и допускают до пяти неверных попыток. Почта для восстановления должна быть привязана к аккаунту. После смены пароля сервер отзывает действующие сессии. Учебный аккаунт `teacher`, созданный командой инициализации, не имеет привязанной почты.
- В форме регистрации роль `student` даёт доступ к вступлению и собственным сдачам. Для роли `teacher` требуется поле `teacher_note`. После подтверждения почты преподаватель может создавать предметы и проверять работы в своих предметах. Запрашиваемая роль не даёт доступа к чужому предмету.
- Cookie сессии имеет срок 7 дней, атрибуты HttpOnly и SameSite=Lax. Для HTTPS задаётся `SG_SECURE_COOKIE=1`. Запрос с истекшей сессией к закрытому API получает 401, запрос участника без нужных прав получает 403. Файлы доступны только через проверяемые маршруты.
- Версия 0.2.0 указана в `info.version` контракта. Базовые пути этой сборки начинаются с `/api`. Выход из формы также использует `POST /logout`. `GET /healthz` возвращает текст и проверяет соединение с SQLite.
