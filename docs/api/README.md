# HTTP API проверки работы

За локальный контракт КТ-2 отвечает Артур Галимов. Версия `0.2.0` от 24.11.2026. [Спецификация OpenAPI 3.0.3](../../api/openapi.yaml)

Пути заданы от корня сервера. Открытый `GET /healthz` возвращает `{"status":"ok"}`, если SQLite доступна. При запросах к работе сервер ищет пользователя и его роль в базе по токену из заголовка `Authorization: Bearer <токен>`. Все ответы содержат JSON в UTF-8 и заголовок `Cache-Control: no-store`. [Истории утверждения и просмотра результата](../requirements/stories.md#us-005-исправить-и-утвердить-результат)

## Какие поля видит пользователь

Запрос `GET /api/submissions/{id}` доступен только преподавателю работы и студенту, который её сдал. Идентификатор должен быть положительным целым числом.

| Статус | Преподаватель | Студент |
| --- | --- | --- |
| `pending_review` | Кроме `id` и `status`, видит максимумы задач в `tasks` и исходные баллы с комментариями в `draft`. | Только `id` и `status` |
| `approved` | Поля студента вместе с `tasks` и `draft`. | К `id` и `status` добавляются оценки `grades` и сумма `total`. Поле `approved_by` указывает ID преподавателя, а `approved_at` хранит время утверждения в UTC. |

В `POST /api/submissions/{id}/approve` преподаватель передаёт один объект JSON с массивом `grades`. На каждую задачу нужна одна строка с номером и баллом от нуля до максимума включительно. После удаления пробельных символов по краям комментарий должен содержать от 1 до 1000 символов Unicode. Сервер принимает строки в любом порядке и возвращает их по номеру задачи. [Пример запроса на 0,7 балла](examples/approve.json)

При утверждении сервер возвращает HTTP 200 с тем же JSON, который получит студент. Из двух одновременных корректных запросов пройдёт только один. После повтора студент видит те же баллы и сведения об их утверждении. [Обработчик HTTP](../../src/api/http.go) · [Транзакция утверждения](../../src/storage/reviews.go) · [Интеграционные тесты](../../tests/review_test.go)

## Ошибки

Строковое поле `error` содержит причину отказа. При попытке выставить 1,2 балла из 1 сервер вернёт HTTP 400 с телом `{"error":"проверьте оценку: для задачи 1 укажите балл от 0 до 1"}` и сохранит прежнее состояние работы.

| HTTP | Когда возникает |
| --- | --- |
| 400 | JSON некорректен или содержит лишнее поле. Сервер также отклоняет неверные строки оценок, даже если работу уже утвердили. |
| 401 | В запросе к работе нет действительного Bearer-токена. Ответ содержит `WWW-Authenticate: Bearer`. |
| 403 | Студент попытался утвердить работу. |
| 404 | Идентификатор неверен или такой работы нет. При запросе чужой работы ответ тот же. |
| 409 | Преподаватель отправил допустимые баллы для уже утверждённой работы. |
| 413 | Тело запроса на утверждение превышает 1 МиБ (1 048 576 байт). |
| 415 | Заголовок `Content-Type: application/json` отсутствует или указан неверно. |
| 500 | Внутренняя ошибка при обращении к хранилищу работ. |
| 503 | На `/healthz` не удалось проверить соединение с SQLite. |

## Исполняемый пример

В окружении или файле `.env` рядом с `compose.yaml` задайте `COMPOSE_PROJECT_NAME=scan-grader-api-demo` и свободный порт в `SG_PORT`. Запускайте отдельный стенд из корня проекта с Docker Compose и Python 3.8 или новее.

```sh
docker compose up --build -d --wait
python tests/demo_api.py
docker compose down
```

На новом томе миграция создаёт работу № 1 с черновой оценкой 0,5 из 1. Получив через CLI токены обеих ролей, скрипт проверяет, что сервер отклоняет 1,2 балла, и утверждает 0,7. Команда `docker compose down` сохраняет том. Следующий запуск проверит сохранённый итог и отказ в повторном утверждении. Код 0 означает успех. [Скрипт демонстрации](../../tests/demo_api.py) · [Исходные учебные данные](../../src/storage/migrations/001_init.sql)

До перезапуска укажите `--result-file before.json`, а после него передайте `--expect-approved --result-file after.json`, чтобы проверить, что работа уже утверждена. Оба файла содержат ответ студенту с автором и временем утверждения в одном формате UTF-8, поэтому их можно сравнить побайтово.

Без Docker передайте путь к исполняемому файлу и тот же `SG_DATA_DIR`, что у сервера. Адрес задаёт `--base-url`.

```sh
python tests/demo_api.py --binary ./scangrader --base-url http://127.0.0.1:8080
```
