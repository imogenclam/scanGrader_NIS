# HTTP API проверки работы

Локальная спецификация КТ-2, версия `0.2.0` от 24.11.2026. За контракт отвечает Артур Галимов. [Спецификация OpenAPI 3.0.3](../../api/openapi.yaml)

Пути начинаются от корня сервера. Открытый запрос `GET /healthz` проверяет соединение с SQLite и возвращает `{"status":"ok"}`. Для чтения и утверждения работы нужен заголовок `Authorization: Bearer <токен>`. Сервер определяет пользователя и его роль по токену в базе. Все три операции возвращают JSON в UTF-8 и заголовок `Cache-Control: no-store`. [Истории утверждения и просмотра результата](../requirements/stories.md#us-005-исправить-и-утвердить-результат)

## Какие поля видит пользователь

`GET /api/submissions/{id}` принимает положительный целочисленный идентификатор. Доступ есть у преподавателя этой работы и у студента, который её сдал.

| Статус | Преподаватель | Студент |
| --- | --- | --- |
| `pending_review` | `id`, `status`, задачи с максимумами в `tasks`, исходные баллы и комментарии в `draft` | Только `id` и `status` |
| `approved` | К прежним полям добавляются `grades`, `total`, `approved_by`, `approved_at` | `id`, `status`, утверждённые строки `grades`, сумма `total`, идентификатор преподавателя `approved_by` и время утверждения UTC `approved_at` |

`POST /api/submissions/{id}/approve` принимает от преподавателя один объект JSON с массивом `grades`. Для каждой задачи нужна одна строка с её номером, баллом от нуля до максимума включительно и комментарием. После удаления пробелов по краям в комментарии должно остаться от 1 до 1000 символов Unicode. Порядок строк во входном массиве произвольный, сервер вернёт их по номеру задачи. Размер тела ограничен 1 МиБ (1 048 576 байт). [Пример запроса на 0,7 балла](examples/approve.json)

Успешное утверждение возвращает HTTP 200 и тот же JSON, который затем получит студент. При повторе с допустимыми баллами сервер возвращает HTTP 409. Повторное чтение возвращает прежние баллы, автора и время утверждения. Два одновременных корректных запроса также приводят к одному утверждению. ## Ошибки

Ответ об ошибке содержит строку `error`. Например, при попытке выставить 1,2 балла из 1 сервер возвращает HTTP 400 и тело `{"error":"проверьте оценку: для задачи 1 укажите балл от 0 до 1"}`. Этот запрос сохраняет предыдущее состояние работы.

| HTTP | Когда возникает |
| --- | --- |
| 400 | При утверждении передан некорректный JSON, лишнее поле или неверные строки оценок. Проверка баллов выполняется и для ранее утверждённой работы. |
| 401 | Для операции со сдачей не передан действительный Bearer-токен. В ответе есть `WWW-Authenticate: Bearer`. |
| 403 | Утверждение запросил студент. |
| 404 | Указан некорректный идентификатор, работа отсутствует или принадлежит другому пользователю. |
| 409 | Преподаватель отправил допустимые баллы для уже утверждённой сдачи. |
| 413, 415 | Тело утверждения превышает 1 МиБ (413), либо отсутствует или неверен `Content-Type: application/json` (415). |
| 500, 503 | Внутренняя ошибка доступа к хранилищу при работе со сдачей (500) или ошибка проверки SQLite на `/healthz` (503). |

## Исполняемый пример

Для отдельного учебного стенда задайте `COMPOSE_PROJECT_NAME=scan-grader-api-demo` и свободный `SG_PORT` в окружении или в файле `.env` рядом с `compose.yaml`. Из корня проекта выполните команды с Docker Compose и Python 3.8 или новее.

```sh
docker compose up --build -d --wait
python tests/demo_api.py
docker compose down
```

На новом томе миграция создаёт сдачу № 1 с черновиком на 0,5 балла из 1. Скрипт получает токены обеих ролей через CLI, проверяет отказ на 1,2 балла и утверждает пример на 0,7. Повторный запуск на том же томе проверяет сохранённый результат и отказ на повторное утверждение. `docker compose down` сохраняет том. Успешная проверка завершается с кодом 0. [Скрипт демонстрации](../../tests/demo_api.py) · [Исходные учебные данные](../../src/storage/migrations/001_init.sql)

Для проверки после перезапуска передайте в первом вызове `--result-file before.json`, а во втором — `--expect-approved --result-file after.json`. Второй вызов требует уже утверждённую сдачу. Оба файла содержат ответ студенту в одинаковой сериализации UTF-8, включая автора и время, и допускают побайтовое сравнение.

Если сервис уже запущен локальным бинарником, укажите путь к нему и используйте тот же `SG_DATA_DIR`, что у сервера. Параметр `--base-url` задаёт адрес явно.

```sh
python tests/demo_api.py --binary ./scangrader --base-url http://127.0.0.1:8080
```
