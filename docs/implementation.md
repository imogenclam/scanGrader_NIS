# Технический срез Scan Grader

Локальная редакция 1 для КТ-2 от 22 ноября 2026 года. Артур Галимов отвечает за сервер Classroom, PDF, ИИ и экран проверки. Алина Лисянская отвечает за аккаунты, интерфейс Classroom, страницу результата, тестирование и стенд.

## Путь преподавателя и студента

1. Преподаватель входит в свой аккаунт, создаёт предмет с названием и необязательным описанием. Сервис возвращает код из шести символов. В предмете преподаватель публикует условия, максимумы по задачам и закрытый эталон `.tex`.
2. Студент регистрируется, подтверждает почту кодом и указывает в профиле ФИО и группу. После вступления по коду ему доступны предмет и условия. В аккаунте с ролью студента запрос эталона получает HTTP 403.
3. Студент сдаёт PDF до 5 страниц и 20 МиБ. Сервис хранит первый принятый файл в закрытом каталоге. При повторной отправке студент получает ссылку на эту работу. Это правило действует и при отправке из двух вкладок.
4. Обработчик сверяет версию эталона, по возможности уменьшает изображения в отдельной копии PDF и запрашивает предварительный балл по каждой задаче. Без настроенного ИИ работа переходит на ручную проверку. Преподаватель открывает оригинал в просмотрщике и видит черновик или причину ручного оценивания.
5. Преподаватель выставляет балл и комментарий по каждой задаче и утверждает результат. До утверждения студент видит статус ожидания. После него автор получает свои итоговые строки, а преподаватель сохраняет доступ к исходному черновику. [Исполняемая проверка по HTTP](../tests/contract/classroom.mjs) · [Схемы](architecture/README.md)

## Настройки локальной поставки

Если оценивание завершилось с ошибкой, при повторной проверке сервис использует ранее распознанный текст этой сдачи. Он заново читает PDF, если изменился оригинал или версия OCR. В закрытый каталог попадает текст только после успешного распознавания всех страниц. При временном сбое SQLite обработчик повторяет запись готовых баллов. Если сохранить черновик по-прежнему не удаётся, преподавателю становится доступна ручная проверка.

| Настройка | Назначение |
| --- | --- |
| `SG_DATA_DIR`, `SG_ADDR` | Путь к SQLite и закрытым файлам, адрес прослушивания. По умолчанию при нативном запуске это `data` и `127.0.0.1:8080`. Compose задаёт `/data` и публикует порт только на loopback хоста |
| `SG_SMTP_HOST`, `SG_SMTP_PORT`, `SG_SMTP_FROM`, `SG_SMTP_USER`, `SG_SMTP_PASSWORD` | При пустом хосте коды записываются в локальные `.eml` в подкаталоге `mail` каталога данных. С SMTP отправка идёт по защищённому соединению, по умолчанию STARTTLS на 587. Для implicit TLS используется порт 465 |
| `SG_OCR_KEY`, `SG_OCR_FOLDER`, `SG_OCR_MODEL` | Ключ и каталог Yandex Cloud OCR, модель распознавания (по умолчанию `math-markdown`) |
| `SG_OCR_REVISION` | Необязательная метка версии OCR. Её меняют, когда провайдер обновил модель под прежним именем и требуется повторное распознавание |
| `SG_MODEL_URL`, `SG_MODEL_NAME`, `SG_MODEL_KEY` | Базовый адрес API по HTTPS, имя модели и ключ. Адаптер добавляет к адресу путь `/chat/completions` |
| `SG_SECURE_COOKIE` | Значение `0` для локального HTTP и `1` для доступа через HTTPS-прокси |

Для нативного запуска значения можно записать в `.env` рядом с `start.cmd`, используя пример проекта. Для Compose тот же файл считывается при создании контейнера. Настройки применяются после перезапуска нативного процесса или команды `docker compose up -d`. Начальный пользователь `teacher` создаётся однократной командой. Студент и преподаватель также могут зарегистрироваться через форму с подтверждением почты. [Пример конфигурации](../.env.example) · [Контракт аккаунтов](api/README.md)

## Границы технической проверки

Сохранение отдельного черновика задания после закрытия формы, проверка соответствия номеров произвольному оформлению решений внутри LaTeX, полные метаданные версии модели и промпта для каждого черновика, измерение точности ИИ и времени преподавателя остаются открытыми по соответствующим историям и НФТ. Поле версии эталона уже связано с конкретной сдачей. Контрактные ответы OCR и модели воспроизводятся на синтетических данных. Реальная сверка по размеченным работам S2 требует настроенного провайдера. [Матрица КТ-2](requirements/traceability.md) · [Бэклог MVP](../backlog.md)
