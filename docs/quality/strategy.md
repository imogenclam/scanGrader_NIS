# Стратегия проверки

Методика КТ-2 от 24 ноября 2026 года. За тестирование пользовательских сценариев и CI отвечает Алина Лисянская. Артур Галимов отвечает за проверку качества ИИ, сжатия сканов и правил оценивания. [Исходное покрытие](baseline.md) · [Матрица требований](../requirements/traceability.md)

## Что проверяется

| Уровень | Среда и данные | Наблюдаемый результат |
| --- | --- | --- |
| Правила предметной области | Go, список задач и подготовленные строки оценки | Принимаются дробные баллы и ноль. Для каждой задачи нужен номер, допустимый балл и комментарий. [Тест оценивания](../../internal/grading/grades_test.go) |
| Сервер и хранилище | HTTP-сервер, временная SQLite с миграциями, раздельные cookie, синтетические PDF | Роли и участие ограничивают доступ. Конкурирующие запросы сохраняют одну сдачу. Черновик переживает исправление и утверждение итога. [Сквозной тест](../../internal/server/flow_test.go) |
| Регистрация и восстановление | Временная SQLite, коды из локальных учебных писем | Адрес подтверждается один раз. Сброс пароля отзывает старые сессии. Участие в предмете требуется и при прямом запросе к API. [Тесты аккаунта](../../internal/server/users_test.go) |
| Подготовка PDF и внешние адаптеры | Синтетические изображения и заранее заданные HTTP-ответы OCR и модели | После сжатия сохраняются страницы. Проверяются формат запроса, передача эталона и отказ при балле выше максимума. [Тест PDF](../../internal/pdf/pdf_shrink_test.go) · [Тест адаптеров](../../internal/ai/pipeline_test.go) |
| Контракт работающего процесса | Чистая временная база, реальный HTTP, две роли. Ключи внешних служб отключены | Повтор даёт ID первой сдачи. Студент получает 403 на запрос эталона. Балл выше максимума даёт 400. После утверждения студенту доступен итог. [Скрипт вызовов](../../tests/contract/classroom.mjs) |
| Браузер и поставка | Node.js 24, Chrome, тот же Go-бинарник. Docker строит образ из исходников | Проверяются сценарий пользователя, типизация, сборка и доступность файлов интерфейса. GitHub Actions сохраняет результаты для SHA запуска. [Workflow](../../.github/workflows/check.yml) |

В CI сначала собирается интерфейс, поскольку Go встраивает готовые файлы React в приложение. Затем GitHub Actions запускает тесты и собирает контейнер. Рабочий процесс проверяет формат Go и историю Git на секреты. Проверяющему доступны отчёты для конкретного SHA. ## Стендовые измерения

Профиль S1 предусматривает одну ВМ с 2 vCPU и 4 ГБ RAM, SQLite на постоянном томе и набор из 10 заданий и 1000 сдач. Профиль S2 содержит 20 синтетических или обезличенных PDF и разметку 40 решений. Для каждого прогона записываются дата, версия кода и зависимостей, конфигурация среды и параметры выборки. [Исходные НФТ и условия S1/S2](../requirements/nfr.md)

| Проверка | Критерий прохождения | Метод |
| --- | --- | --- |
| PERF-01 / NFR-001 | p95 статуса и p95 чтения итога по отдельности ≤ 500 мс | На S1 после 2 мин прогрева подать суммарно 10 запросов/с в течение 5 мин без внешнего ИИ. Сохранить обе выборки |
| FAIL-01 / NFR-002 | В 6 из 6 отказов доступны оригинал, причина ручной проверки и возможность утверждения | Проверить таймаут, исчерпание квоты, недоступность, нечитаемый скан, неверный JSON и балл выше максимума |
| SEC-01 / NFR-003 | 0 выдач чужого PDF, эталона, черновика или результата. В теле вызова ИИ отсутствуют поля ФИО и группы из профиля | Матрица гостя, двух студентов и двух преподавателей в двух предметах, положительные и отрицательные вызовы |
| OBS-01 / NFR-004 | Для 10 из 10 обработок журнал связывает ID, этап, статус и длительность. Содержимое файлов, профилей, ключей и кодов остаётся закрытым | Сопоставить события пяти успешных и пяти неуспешных проверок |
| OPS-01 / NFR-005 | Чистый запуск и обновление по инструкции проходят, данные предмета и PDF читаются после обновления | На отдельной ВМ пройти запуск, проверить `/healthz`, создать сдачу, сменить версию и прочитать оригинал |
| MAINT-01 / NFR-006 | Все перечисленные правила проходят при отключённых внешних API | Прогнать тесты диапазона/полноты, видимости черновика и единственности сдачи для SHA сдачи |
| DATA-01 / NFR-007 | RPO ≤ 24 ч и RTO ≤ 60 мин. Число записей, хеши эталонов и оригиналов совпадают с описью снимка | Восстановить согласованную копию на отдельный том, засечь время и проверить ранее утверждённый итог |
| AI-01 / NFR-008 | Отклонение от разметки ≤ 0,2 максимума минимум в 80% вычислений и 70% доказательств | Отдельно оценить 20 вычислений и 20 доказательств S2, включая не менее 5 корректных альтернативных доказательств. Пропуск считается промахом |
| AI-02 / NFR-009 | До 28 внешних запросов на работу из пяти страниц за одну попытку. Цель по стоимости составляет до 10 ₽ за попытку и до 200 ₽ за серию из 20 работ без повторов | Сопоставить вызовы с ID сдачи и рассчитать стоимость по тарифу на дату испытания. При повторном оценивании полный сохранённый текст позволяет пропустить OCR. При двух полных попытках верхняя граница составляет 56 запросов |
| PDF-01 / NFR-010 | Принятая рабочая копия меньше исходника, до 20 МиБ и с тем же числом страниц. Снижение доли верно прочитанных значимых символов ≤ 5 п. п. | На ≥ 5 пригодных для сжатия PDF сравнить байты, страницы и значения на одинаковых размеченных фрагментах до и после сжатия |
| AI-03 / NFR-011 | p95 времени до черновика ≤ 120 с | Обрабатывать работы S2 по очереди. Для готовых черновиков измерить интервал от начала обработки. Отдельно указать долю отказов и таймаутов |
| AI-04 / NFR-012 | Для 100% черновиков известны версия эталона, модель, версия промпта и дата | Сверить метаданные со входным набором, конфигурацией провайдера и исходниками промпта. Сейчас с каждой сдачей сохраняется версия эталона |

## Проверочный эксперимент с ИИ

В эксперименте `TestRenderedScanToDraft` рендерер читает страницу синтетического PDF. Тест декодирует отправленное изображение и проверяет, что на нём видна запись. Затем он проверяет присутствие распознанной формулы и эталона в запросе оценки. Контрольный ответ даёт один балл из одного. В отдельном тесте адаптер принимает 0,7 балла и отклоняет 1,2 при максимуме 1. [Эксперимент со сканом](../../internal/ai/scan_test.go) · [Проверка диапазона](../../internal/ai/pipeline_test.go)

Для внешнего прогона Артур фиксирует обезличенный набор S2, эталоны, разметку, дату, идентификаторы OCR, модели и версию промпта. По каждой попытке он записывает длительность, ответ или причину ручной проверки, число тарифицируемых запросов и стоимость по фактически применённому тарифу. По разметке считаются доли совпадений отдельно для вычислений и доказательств. Изменение качества после сжатия измеряется на одних и тех же фрагментах.

Целевые суммы AI-02 задают критерий для испытания на S2. Фактический расход и качество оценки будут измерены при обращении к внешним сервисам. [Лимиты обращений](../../internal/ai/transport.go) · [Параметры распознавания](../../internal/ai/yandex_ocr.go)
