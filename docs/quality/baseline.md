# Исходное покрытие и результаты локальной проверки

Рабочий протокол команды Scan Grader от 24 ноября 2026 года. Измерения относятся к техническому каркасу КТ-2 с учебной сдачей № 1. [Описание и запуск](../../README.md#технический-сценарий-кт-2)

## Утверждение оценки

Прошли три Go-теста. Один проверяет правила выставления дробного балла, а два других обращаются к обработчикам HTTP и используют временную файловую базу SQLite. [Правила оценивания](../../src/grading/grades_test.go) · [Интеграционные тесты](../../tests/review_test.go)

| Условие | Наблюдаемый результат |
| --- | --- |
| Студент открывает работу до утверждения | Ответ содержит номер сдачи и статус `pending_review`. Черновик доступен преподавателю |
| Преподаватель выставляет 1,2 балла при максимуме 1 | Сервер возвращает HTTP 400. У студента сохраняется статус ожидания |
| Студент пытается утвердить оценку | Сервер возвращает HTTP 403 |
| Преподаватель утверждает 0,7 балла | Студент получает 0,7 балла и комментарий «Арифметическая ошибка». Повторное открытие базы сохраняет результат, имя утвердившего и время утверждения |
| Одновременно отправлены допустимые оценки 0,7 и 0,3 | Один запрос получает HTTP 200, а другой получает HTTP 409. Студенческий GET совпадает с полным ответом запроса, который первым утвердил работу |

Пример выполнен через HTTP в отдельном контейнере Docker Compose. После перезапуска запрос студента вернул тот же балл 0,7, исходный комментарий на русском языке и прежнее время утверждения. Скрипт CI сохраняет студенческий ответ до и после перезапуска и побайтно сравнивает файлы. [Исполнимый сценарий](../../tests/demo_api.py) · [Локальные и серверные проверки](../../ci/check.sh)

## Покрытие Go-кода

Прогон выполнен с Go 1.26.11 для Windows amd64. Общий профиль учитывает пакеты в `src/`, включая HTTP, хранилище и точку входа сервера. При расчёте каждый оператор, выполненный хотя бы одним тестом, учитывается один раз.

| Область | Выполнено операторов | Покрытие |
| --- | ---: | ---: |
| Весь Go-код каркаса | 158 из 216 | 73,1 % |
| Пакет `src/grading` | 17 из 27 | 63,0 % |

Из корня проекта выполните команды для повторного измерения. Строка `total` показывает общий результат. Показатель пакета `src/grading` рассчитан по блокам этого пакета в том же профиле. Измерение охватывает только операторы Go в текущей версии каркаса.

```sh
go test -count=1 '-coverpkg=./...' '-coverprofile=coverage.out' ./...
go tool cover '-func=coverage.out'
```

## Распознавание скана

В двух учебных PDF формула представлена изображением без текстового слоя. Исходный растр имеет размер 1060 × 280 пикселей при размере страницы 530 × 140 пунктов, что соответствует 144 dpi. Сначала Poppler подготовил изображения при 180 dpi. Затем опыт повторили при 144 dpi на тех же файлах, с той же настройкой Tesseract и тем же эталоном. Распознанную формулу и эталон в LaTeX скрипт передаёт локальному сервису оценивания с заранее заданным ответом. [Скрипт эксперимента](../../tests/scan_experiment.py) · [Эталон](../../tests/testdata/reference.tex) · [Версии инструментов](../../tests/experiment.Dockerfile)

| Учебный скан | Контроль при 180 dpi | Основной прогон при 144 dpi |
| --- | --- | --- |
| [Сумма с ответом 4](../../tests/testdata/four.pdf) | `2+2=4`, тестовый сервис вернул 1 балл | `2+2=4`, тестовый сервис вернул 1 балл |
| [Сумма с ответом 5](../../tests/testdata/five.pdf) | `2+2=09`, опыт прерван до обращения к оценщику | `2+2=5`, тестовый сервис вернул 0 баллов |

При 144 dpi полностью прочитаны обе печатные формулы, при 180 dpi одна из двух. Проверка по каждому примеру завершается ошибкой, если выражение или ожидаемый тестовый балл расходятся. Для воспроизведения неудачного контрольного прогона добавьте `--dpi 180` к последней команде. Качество проверки рукописных работ действующей моделью, её время и стоимость предстоит измерить отдельно на наборе S2.

```sh
docker build -t scangrader-ocr-test -f tests/experiment.Dockerfile .
docker run --rm --network none scangrader-ocr-test
```

## Версия и воспроизведение

Локальная проверка выполняется командой `bash ci/check.sh` из чистой копии. В каталоге `test-results/` файл `commit-sha.txt` связывает отчёты с исходниками. Там же сохраняются журнал Go-тестов, профиль покрытия, результаты поиска секретов, сборки, запросов HTTP и опыта с PDF. GitHub Actions настроен вызывать этот же скрипт и прикладывать отчёты к запуску для проверенного SHA. Удалённый прогон и тег относятся к последующей фиксации сдачи. [Workflow](../../.github/workflows/check.yml)
