# Исходное покрытие и результаты локальной проверки

24 ноября 2026 года команда Scan Grader проверила каркас КТ-2 на учебной работе № 1. [Описание и запуск](../../README.md#технический-сценарий-кт-2)

## Утверждение оценки

Прошли три Go-теста. Один проверял правила дробного балла, а два других вызывали обработчики HTTP с временной файловой базой SQLite. [Модульный тест](../../src/grading/grades_test.go) · [Интеграционные тесты](../../tests/review_test.go)

| Условие | Результат |
| --- | --- |
| Студент открывает работу до утверждения | Ему видны только номер и статус `pending_review`. Черновик видит преподаватель |
| Преподаватель ставит 1,2 балла при максимуме в 1 балл | Сервер возвращает HTTP 400 и оставляет работу на проверке |
| Студент пытается утвердить оценку | Сервер возвращает HTTP 403 |
| Преподаватель утверждает 0,7 балла | Студент видит 0,7 балла с комментарием «Арифметическая ошибка». Когда база открывается повторно, в ней сохраняются также автор и время утверждения |
| Два запроса одновременно утверждают 0,7 и 0,3 балла | Один получает HTTP 200, а другой получает HTTP 409. Студент видит результат того запроса, который завершился с HTTP 200 |

При проверке через Docker Compose ответ студенту до перезапуска контейнера и после него совпал побайтно. [Демонстрация через HTTP](../../tests/demo_api.py) · [Сравнение ответов в CI](../../ci/check.sh)

## Покрытие Go-кода

Тесты выполнены с Go 1.26.11 на Windows amd64. В профиль вошли все пакеты `src/`, включая точку входа сервера. Каждый выполненный оператор учтён один раз.

| Область | Выполнено операторов | Покрытие |
| --- | ---: | ---: |
| Весь Go-код каркаса | 158 из 216 | 73,1 % |
| Пакет `src/grading` | 17 из 27 | 63,0 % |

Для повторного измерения выполните команды из корня проекта. Строка `total` показывает общее покрытие. Показатель для `src/grading` рассчитан по блокам этого пакета в том же профиле.

```sh
go test -count=1 '-coverpkg=./...' '-coverprofile=coverage.out' ./...
go tool cover '-func=coverage.out'
```

## Распознавание скана

В каждом учебном PDF напечатана одна формула без текстового слоя. Изображение размером 1060 × 280 пикселей занимает страницу 530 × 140 пунктов, поэтому исходному разрешению соответствует 144 dpi. Оба файла обработали при 180 и 144 dpi с одинаковыми настройками Tesseract. Страницы подготовил Poppler. Скрипт передавал распознанное выражение и эталон в LaTeX тестовому сервису с заранее заданными баллами. [Эксперимент](../../tests/scan_experiment.py) · [Эталон](../../tests/testdata/reference.tex) · [Версии инструментов](../../tests/experiment.Dockerfile)

| Учебный скан | Контроль при 180 dpi | Основной прогон при 144 dpi |
| --- | --- | --- |
| [Сумма с ответом 4](../../tests/testdata/four.pdf) | `2+2=4` (1 балл) | `2+2=4` (1 балл) |
| [Сумма с ответом 5](../../tests/testdata/five.pdf) | OCR прочитал `2+2=09`, поэтому скрипт остановился до оценивания | `2+2=5` (0 баллов) |

Команды ниже повторяют прогон при 144 dpi. Скрипт завершается ошибкой, если формула или балл расходятся с ожидаемыми. Для контрольного прогона добавьте `--dpi 180` к последней команде. На наборе S2 предстоит измерить, насколько точно рабочая модель оценит рукописные решения, сколько займёт проверка и сколько она будет стоить.

```sh
docker build -t scangrader-ocr-test -f tests/experiment.Dockerfile .
docker run --rm --network none scangrader-ocr-test
```

## Версия и воспроизведение

Запустите `bash ci/check.sh` из чистой копии. В каталоге `test-results/` появятся протоколы и профиль покрытия. Файл `commit-sha.txt` указывает проверенный коммит. При запуске в GitHub Actions эти файлы прикладываются к проверке того же коммита. [Workflow](../../.github/workflows/check.yml)
