# ADR-002. SQLite и атомарное утверждение

Решение принято 24 ноября 2026 года для КТ-2. За схему данных отвечают Артур Галимов и Алина Лисянская.

## Контекст

Студент должен видеть одну и ту же оценку после перезапуска и при двух одновременных утверждениях. Опубликовать её может только преподаватель этой работы. Эти условия связывают US-005 и US-006 с требованиями к доступу и сохранности данных. [NFR-003, NFR-006 и NFR-007](../requirements/nfr.md)

## Выбор

SQLite хранит файл `/data/scangrader.db` на постоянном томе. Каждый процесс использует одно соединение SQLite с включёнными внешними ключами и режимом WAL. В транзакции `IMMEDIATE` он находит работу преподавателя и проверяет баллы по всем задачам. Вместе с оценками сервис записывает, кто и когда их утвердил. Студент видит результат после фиксации транзакции. [Схема данных](../architecture/d04-data.svg) · [Запись результата](../../src/storage/reviews.go) · [Миграция](../../src/storage/migrations/001_init.sql)

| Альтернатива | Основание для отказа |
| --- | --- |
| PostgreSQL в отдельном контейнере | PostgreSQL допускает запись из нескольких экземпляров. На учебной ВМ пока работает один, а отдельный сервер БД потребовал бы настройки доступа и обновлений |
| JSON-файл для каждой работы | Для согласованного обновления связанных записей пришлось бы самим реализовать блокировки и определить, как восстанавливать данные после сбоя |

## Последствия и пересмотр

SQLite выполняет записи по очереди. Если два запроса содержат допустимые баллы, один утвердит оценку, а другой получит HTTP 409. Команда испытает PostgreSQL, если понадобятся несколько пишущих экземпляров или ожидание записи на S1 приведёт к превышению порога NFR-001. Восстановление после потери тома проверяется отдельно по DATA-01. [Конфликт запросов](../architecture/d06-failure.svg) · [Порядок отката](../operations/deployment.md)
