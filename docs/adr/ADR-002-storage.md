# ADR-002. SQLite и закрытый файловый том

КТ-2, редакция 1 от 22 ноября 2026 года. Решение принято для однопроцессного стенда. Схему совместно ведут Артур Галимов и Алина Лисянская.

## Контекст

Два параллельных запроса студента должны вернуть одну сдачу. При оценивании преподавателю нужны исходный PDF, действовавшая при сдаче версия эталона и история различий между черновиком и итогом. На одной ВМ доступны локальный диск и постоянный том. Затронуты US-001, US-003, US-005, NFR-003 и NFR-007.

## Рассмотренные варианты

| Вариант | Последствие для проекта |
| --- | --- |
| PostgreSQL и объектное хранилище файлов | Допускают несколько реплик приложения и отдельные политики хранения. На учебном стенде добавляют подключения, конфигурацию и две процедуры восстановления |
| SQLite со всеми PDF и эталонами в полях BLOB | Можно копировать единый файл БД. Приём больших сканов нагружает транзакции, а для обработки всё равно нужны файловые представления |
| SQLite для метаданных и файлы на том же закрытом томе | База обеспечивает уникальность сдачи, а PDF-обработчик получает обычный файл. Восстановление требует согласованной копии всего тома |

## Решение

SQLite работает в режиме WAL с включёнными внешними ключами. Пара `(assignment_id, student_id)` уникальна. При конкурирующей вставке API возвращает ID уже принятой сдачи, а лишний временный файл удаляет. Сервер хранит путь к оригиналу и SHA-256 эталона. Перед обращением к модели он сверяет версию и содержимое эталона. Рекомендация и утверждённая оценка находятся в разных полях. Миграции запускаются транзакцией при открытии БД. ## Последствия и пересмотр

Остановка перед копированием всего тома позволяет согласовать БД, файлы и служебные данные SQLite. Замеры RPO и RTO на учебной ВМ запланированы. При необходимости второго одновременно пишущего экземпляра или превышении порога NFR-001 на S1 следует пересмотреть выбор СУБД и хранилища.
