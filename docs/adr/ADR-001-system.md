# ADR-001. Модульный монолит и общий источник интерфейса и API

КТ-2, редакция 1 от 22 ноября 2026 года. Решение принято для технического каркаса. Владельцы — Артур Галимов и Алина Лисянская.

## Контекст

Студент и преподаватель работают с одними и теми же предметами, заданиями и статусами. Два участника команды обслуживают один учебный стенд. Для обращения к предмету или PDF серверу нужны одновременно сессия пользователя, его роль и связь с этим предметом. Это следует из US-001, US-002, US-003, US-006, US-007 и NFR-003.

## Рассмотренные варианты

| Вариант | Последствие для проекта |
| --- | --- |
| Отдельные сервисы аккаунтов, Classroom и проверки | Можно независимо масштабировать обработку. Для текущего стенда потребуются сетевые контракты для проверки прав, координация версий и несколько процессов поставки |
| Отдельные публикации SPA и API | Интерфейс можно обновлять самостоятельно. Раздельные источники требуют настройки cookie, адресов и политики доступа браузера |
| Один исполняемый файл Go с собранным React | Сервер проверяет права непосредственно перед чтением данных. Интерфейс и API обновляются вместе |

## Решение

Сервер Go отдаёт статические ресурсы React и HTTP API. Маршруты находятся в `internal/server`, правила баллов в `internal/grading`, операции Classroom в `internal/classroom`. Запросы из браузера используют сессию в HttpOnly-cookie. Файлы доступны через маршруты, которые проверяют доступ к конкретному заданию или сдаче. Обработчик ИИ работает в фоне в том же экземпляре.

## Последствия и пересмотр

На стенде одна версия схемы HTTP и одна сборка интерфейса. Перезапуск приложения затрагивает оба слоя и обработку сдач. Отдельный процесс обработки стоит выделить, если профиль S1 покажет конкуренцию за процессор, из-за которой p95 запросов статуса превышает 500 мс. Связь с интерфейсом и граница доступа отражены на D-01 и D-02. [Схемы](../architecture/README.md) · [NFR-001 и NFR-003](../requirements/nfr.md)
