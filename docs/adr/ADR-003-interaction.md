# ADR-003. Синхронное утверждение результата через REST

Решение принято 24 ноября 2026 года для КТ-2. За контракт отвечает Артур Галимов.

## Контекст

Преподавателю нужно знать, опубликована ли оценка (US-005). Студенту доступны только утверждённые баллы (US-006), поскольку в черновике возможны ошибки. Права на публикацию и порядок проверки этих правил заданы в NFR-003 и NFR-006. [Истории](../requirements/stories.md) · [Требования](../requirements/nfr.md)

## Выбор

Преподаватель передаёт оценки по всем задачам одним запросом `POST /api/submissions/{id}/approve`. Сервер возвращает HTTP 200 после записи в SQLite. Если ответ потерялся, результат можно узнать через `GET /api/submissions/{id}`. Повторный запрос с допустимыми баллами получает HTTP 409. Для проверки доступа сервис выдаёт учебные Bearer-токены. [Контракт OpenAPI](../../api/openapi.yaml) · [Последовательность вызовов](../architecture/d05-review.svg)

| Альтернатива | Основание для отказа |
| --- | --- |
| gRPC между клиентом и сервисом | Типизированные сообщения пригодились бы нескольким внутренним клиентам. Здесь две операции с работой можно проверить обычным HTTP-клиентом |
| Отправка команды через очередь | Клиент узнал бы лишь о приёме команды. Чтобы узнать о публикации, пришлось бы хранить промежуточный статус и проверять доставку сообщения |

## Последствия и пересмотр

Публикация не зависит от длительности распознавания. В КТ-2 черновик уже записан в учебной базе, а распознавание формулы проверено с тестовым оценщиком. Рабочую модель команда выберет по результатам испытаний на наборе S2. Способ публикации стоит пересмотреть, если для утверждения потребуется долгий внешний вызов или другие сервисы начнут отслеживать публикацию оценки.
