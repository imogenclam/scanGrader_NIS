# Матрица трассируемости КТ-2

Матрицу ведёт Артур (P1), а сценарии проверяет Алина (P4). Редакция от 24 ноября 2026 года охватывает критерии [семи историй MVP](stories.md) и условия испытаний [12 НФТ](nfr.md). [Версия пакета](../../README.md#контрольные-точки) · [Результаты прогонов КТ-2][отчёт]

В каркасе `GET /api/submissions/{id}` выдаёт сдачу с учётом роли, а `POST /api/submissions/{id}/approve` сохраняет итог. `GET /healthz` проверяет доступность SQLite. Остальные операции, включая Classroom и приём PDF, запланированы для MVP. Границу сервиса для US-001, US-002, US-003 и US-007 задают [D-01] и [ADR-001]. На [D-02] показано место обработки скана, а [ADR-003] объясняет, почему итог публикуется отдельно. [Контракт HTTP][контракт] · [Примеры вызовов][примеры]

**PASS** означает, что каркас подтвердил поведение. При **ЧАСТИЧНО** проверена часть критерия, а **PLAN** обозначает запланированный сценарий. Номер AT соответствует критерию в карточке истории.

## Истории и критерии приёмки

| История и критерий | Операция и ответственный компонент | Проверка, результат КТ-2 и оставшаяся работа |
| --- | --- | --- |
| US-001 / AC-001 | Classroom и хранилище эталонов, [D-01] | **PLAN**, AT-001. Опубликовать задание с тремя задачами в своём предмете и сверить версию эталона. Участник находит задание в списке и открывает условия. |
| US-001 / AC-002 | Проверка файла эталона. Classroom, [D-01] | **PLAN**, AT-002. При неверном формате, повторе номера или пропуске максимума задание остаётся черновиком, а сервис сообщает причину. |
| US-001 / AC-003 | Выдача файлов предмета, [D-01] | **PLAN**, AT-003. Участник открывает условия, а прямой запрос студента к эталону отклоняется без выдачи файла. |
| US-001 / AC-023 | Право публикации. Classroom, [D-01] | **PLAN**, AT-023. Другой преподаватель получает отказ, и список заданий остаётся прежним. |
| US-002 / AC-004 | Нормализация кода. Classroom, [D-01] | **PLAN**, AT-004. Ввести ` ab2cd3 ` с полным профилем. Предмет открывается и появляется в списке, а студент видит опубликованные задания. |
| US-002 / AC-005 | Профиль и Classroom, [D-01] | **PLAN**, AT-005. Поочерёдно пропустить ФИО и группу. Участие появляется только после исправления. |
| US-002 / AC-020 | Поиск по коду. Classroom, [D-01] | **PLAN**, AT-020. При неизвестном коде сервис сообщает об ошибке и сохраняет прежний список предметов. |
| US-002 / AC-021 | Хранилище участников, [D-01] | **PLAN**, AT-021. При повторном вводе верного кода открывается тот же предмет с одной записью в списке. |
| US-002 / AC-024 | Вход в кабинет. Аккаунты, [D-01] | **PLAN**, AT-024. Самостоятельно зарегистрироваться и войти студентом. В кабинете доступна форма профиля. |
| US-002 / AC-025 | Роль студента. Аккаунты и Classroom, [D-01] | **PLAN**, AT-025. После самостоятельной регистрации попытаться создать предмет и опубликовать задание. Сервер отклоняет оба запроса. |
| US-003 / AC-006 | Привязка к студенту и заданию. Приём PDF, [D-01] | **PLAN**, AT-006. Сдать трёхстраничный PDF размером 2 МБ и сверить оригинал. Студент получает подтверждение, а преподаватель видит одну сдачу в списке. |
| US-003 / AC-007 | Проверка типа файла. Приём PDF, [D-01] | **PLAN**, AT-007. Загрузить повреждённый PDF и по отдельности превысить лимиты размера и числа страниц. Сервис объясняет отказ и не создаёт принятую сдачу. |
| US-003 / AC-008 | Приём PDF и хранилище сдач, [D-01] | **PLAN**, AT-008. Повторить загрузку и проверить одновременную отправку двух PDF. В обоих случаях остаётся одна принятая сдача с хешем первого принятого файла. |
| US-003 / AC-022 | Проверка участия в предмете, [D-01] | **PLAN**, AT-022. Если студент вне предмета напрямую запросит условия и отправит PDF, сервер отклонит оба запроса без выдачи условий и создания сдачи. |
| US-004 / AC-009 | Адаптер оценки и валидатор черновика, [D-02], [ADR-003] | **ЧАСТИЧНО**. [Тест][баллы] проверяет порядок трёх принятых строк с баллами 1, 0,3 и 0,7. **PLAN**, AT-009. По ответу оценщика преподаватель видит статус «готов черновик» и три строки с комментариями. |
| US-004 / AC-010 | Проверка по эталону. Адаптер модели, [D-02], [ADR-003] | **PLAN**, AT-010 и AI-01. Реальная модель даёт полный балл за верное доказательство другим способом на заранее размеченном примере. |
| US-004 / AC-011 | Ручная проверка. Обработчик и хранилище PDF, [D-02], [ADR-003] | **PLAN**, AT-011. При нечитаемом скане, сбое или балле 1,2 из 1 преподаватель видит причину и статус ручной проверки. Исходник доступен, а ошибочной рекомендации нет. |
| US-005 / AC-012 | Однократное утверждение. POST, валидатор и SQLite, [D-04], [D-05], [ADR-002] | **ЧАСТИЧНО**. [HTTP-тест][http] меняет 0,5 на 0,7 в одной задаче и сохраняет комментарий. Прежний черновик читается отдельно. **PLAN**, AT-012. В интерфейсе исправить вторую из трёх оценок с 0,3 на 0,5 и сверить итог с PDF. |
| US-005 / AC-013 | Проверка полей при POST утверждения, [D-05], [ADR-001] | **PASS** на HTTP API, AT-013. При 1,2 балла из 1, пропуске балла или пустом комментарии [тест][http] получает 400 без смены статуса студента. [Скрипт][демо] сверяет текст ошибки для 1,2. [Валидатор][правила] указывает номер задачи при ошибке диапазона или пустом комментарии. |
| US-005 / AC-014 | Ручная публикация, [D-02], [ADR-003] | **PLAN**, AT-014. После сбоя сдача переходит на ручную проверку. Когда преподаватель вручную заполнит строки и утвердит их, студент увидит итог. |
| US-006 / AC-015 | Черновик при GET сдачи, [D-04], [D-05], [ADR-001] | **PASS** на HTTP API, AT-015. До утверждения [тест][http] сверяет полный ответ студенту с двумя полями `id` и `status=pending_review`. Баллы черновика и комментарий видит преподаватель. |
| US-006 / AC-016 | Чтение итога. GET сдачи и SQLite, [D-04], [D-05], [ADR-002] | **ЧАСТИЧНО**. Повторно открыв БД, [HTTP-тест][http] читает одну строку с 0,7 балла и исправленным комментарием. **PLAN**, AT-016. Автор видит на своей странице три утверждённые строки с 0,5 балла во второй. |
| US-006 / AC-017 | GET сдачи и будущая выдача PDF, [D-02], [D-04], [ADR-002] | **PLAN**, AT-017. [БД][хранилище] отбирает сдачи по владельцу и назначенному преподавателю. В базе один студент. Для приёмки второй запрашивает чужую существующую сдачу и её PDF и получает отказ. |
| US-007 / AC-018 | Создание предмета. Classroom, [D-01] | **PLAN**, AT-018. «Математический анализ» появляется в списке создавшего его преподавателя и получает уникальный шестисимвольный код. |
| US-007 / AC-019 | Название предмета. Classroom, [D-01] | **PLAN**, AT-019. При пустом названии сервис просит его заполнить и не создаёт предмет. |

## Нефункциональные требования

Полные испытания запланированы для MVP. На КТ-2 частично проверены три требования.

| Требование | Компонент, схема, решение | Метод и статус |
| --- | --- | --- |
| NFR-001. Время чтения | GET сдачи и SQLite. [D-02], [ADR-001], [ADR-002] | **PLAN**, [PERF-01](nfr.md#nfr-001-время-чтения-сдачи). Две выборки задержек на S1 по статусам сдач. |
| NFR-002. Отказ обработки | Обработчик скана и хранилище оригиналов (MVP). [D-02], [ADR-002], [ADR-003] | **PLAN**, [FAIL-01](nfr.md#nfr-002-сохранение-работы-при-сбое-проверки). После каждого из шести сбоев утвердить принятую работу вручную. |
| NFR-003. Доступ | Проверка роли в HTTP API и владельца в SQLite. Участие и файлы в плане MVP. [D-02], [D-04], [ADR-001], [ADR-002] | **ЧАСТИЧНО**. [Тест][http] проверяет 401, 403 и закрытый черновик. Полная матрица [SEC-01](nfr.md#nfr-003-разграничение-доступа) запланирована. |
| NFR-004. Наблюдаемость | Журнал обработки PDF и оценки (MVP). [D-02], [ADR-003] | **PLAN**, [OBS-01](nfr.md#nfr-004-диагностика-обработки). Связать события десяти известных исходов без раскрытия данных. |
| NFR-005. Запуск и обновление | Контейнер Go и SQLite на именованном томе. [D-03], [ADR-002] | **ЧАСТИЧНО**. [Прогон Compose][отчёт] подтвердил запуск и чтение оценки после перезапуска. Осталось обновить версию и сверить данные и PDF по [OPS-01](nfr.md#nfr-005-запуск-и-обновление). |
| NFR-006. Проверяемость правил | Валидатор и выдача черновика. Приём сдач запланирован. [D-02], [D-04], [ADR-001], [ADR-002] | **ЧАСТИЧНО**. [Тесты баллов][баллы] и [HTTP][http] проверяют диапазон, полноту и приватность. Для [MAINT-01](nfr.md#nfr-006-автоматическая-проверка-предметных-правил) нужен AT-008. |
| NFR-007. Восстановление | SQLite, постоянный том и будущая копия файлов. [D-03], [D-04], [ADR-002] | **PLAN**, [DATA-01](nfr.md#nfr-007-восстановление-данных). Измерить время восстановления согласованной копии и сверить файлы. |
| NFR-008. Точность | Распознавание и оценка (MVP). [D-02], [ADR-003] | **PLAN**, [AI-01](nfr.md#nfr-008-точность-предварительных-оценок) на S2. [Опыт][опыт] охватил чтение двух формул и обмен с локальным двойником. |
| NFR-009. Бюджет | Лимиты адаптеров распознавания и оценки (MVP). [D-02], [ADR-003] | **PLAN**, [AI-02](nfr.md#nfr-009-бюджет-одной-проверки). Число вызовов и стоимость по попыткам и за серию. |
| NFR-010. Сжатие | Рабочая копия и оригинал PDF (MVP). [D-02], [ADR-002], [ADR-003] | **PLAN**, [PDF-01](nfr.md#nfr-010-размер-и-читаемость-рабочей-копии-pdf). До и после сжатия сравнить размер, число страниц и долю верных символов. |
| NFR-011. Время проверки | Подготовка скана и ожидание оценщика (MVP). [D-02], [ADR-003] | **PLAN**, [AI-03](nfr.md#nfr-011-время-до-черновика). Замер от начала обработки до черновика по всей серии S2. |
| NFR-012. Происхождение оценки | Эталон и конфигурация в черновике (MVP). [D-02], [ADR-002], [ADR-003] | **PLAN**, [AI-04](nfr.md#nfr-012-происхождение-черновика). Сверить метаданные каждого черновика с конфигурацией прогона. |
