## Состояния сдачи

При первой загрузке сервер записывает оригинал и создаёт строку `queued`. Обработчик атомарно переводит её в `processing`. Корректный ответ по всем задачам переводит работу в `draft`. При сбое, отсутствии ключей или прерывании обработки перезапуском сервис сохраняет причину и переводит работу в `manual`. Преподаватель предмета может один раз вернуть работу из `manual` в `queued`, если подключена ИИ-проверка.

Состояние `approved` возникает только по решению преподавателя из `draft` или `manual`. Черновик остаётся доступен преподавателю после утверждения. В личном кабинете автора до этого виден статус `waiting`, после утверждения появляются итоговые баллы и комментарии. [Обработчик очереди](../../internal/server/worker.go) · [Доступ к сдаче и утверждение](../../internal/server/submissions.go)

После успешного чтения всех страниц обработчик сохраняет текст в закрытом файловом томе. При повторной проверке он сверяет хеш оригинала и версию OCR. Если сбой произошёл при записи готового черновика в SQLite, обработчик повторяет запись полученных баллов. [Повтор оценивания](../../internal/ai/transcript_retry_test.go) · [Сбой записи](../../internal/server/worker_retry_test.go)
