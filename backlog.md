# Бэклог MVP Scan Grader

Бэклог ведёт Артур (P1). Без задач P0 сквозной сценарий не заработает, а задачи P1 нужны для приёмки MVP. Оценки в человеко-днях охватывают полный объём работ. [Роли P1–P4](README.md) · [Что проверено на КТ-2](docs/requirements/traceability.md)

| ID | Задача и проверяемый результат | Связь | Приоритет | Владелец | Оценка | Зависимости |
| --- | --- | --- | --- | --- | --- | --- |
| SG-01 | Создать модель заданий с миграциями. В своём предмете преподаватель задаёт условия и баллы, а затем добавляет закрытый эталон. Страницу опубликованного задания для участников реализует Алина | US-001, NFR-003, NFR-007 | P0 | P1 | 3 дн. | SG-11 |
| SG-02 | Алина проектирует основные экраны. После регистрации и входа студент указывает ФИО и группу в личном кабинете. Алина готовит миграции пользователей и профилей, а для демонстрации создаёт аккаунт преподавателя. Форма вступления через API Classroom Артура открывает предмет по верному коду. При ошибке или повторе лишняя запись не появляется | US-002, NFR-003 | P0 | P2 | 4 дн. | SG-11 для проверки вступления |
| SG-03 | Сервер хранит исходный PDF на постоянном томе и при повторе оставляет первую сдачу. Если файл отклонён, сервер объясняет причину. Алина подключает загрузку и показ статуса на странице задания | US-003, NFR-001, NFR-003, NFR-007, NFR-010 | P0 | P3 | 3 дн. | SG-01, SG-02 |
| SG-04 | Распознавание и обмен с оценщиком проверены на двух учебных PDF. Для выбора рабочей модели используется набор размеченных сканов. Подготовленный PDF сохраняет читаемость формул и после сжатия. При сбое сдача доступна для ручной проверки | US-004, NFR-002, NFR-004, NFR-009–NFR-012 | P0 | P3 | 4 дн. | SG-03 для подключения к сдаче |
| SG-05 | Подключить выбранный способ ИИ-проверки скана по эталону в `.tex`. Проверять, что по каждой задаче есть допустимый балл с коротким пояснением | US-004, NFR-002, NFR-008, NFR-009, NFR-011, NFR-012 | P0 | P3 | 4 дн. | SG-01, SG-04 |
| SG-06 | По дизайну Алины Артур реализует экран с PDF рядом с черновиком и настраивает сохранение утверждённой оценки. Алина выводит её на странице студента | US-005, US-006, NFR-001, NFR-003, NFR-004, NFR-006 | P0 | P3 | 4 дн. | SG-03, SG-05 |
| SG-07 | Алина проверяет путь от регистрации до оценки и права на предмет и файл. Тестирует параллельную загрузку работ и сохранение оценок в SQLite. После восстановления БД и файлов сверяет ссылки в записях с исходными PDF | US-001, US-002, US-003, US-005, US-006, US-007, NFR-003, NFR-006, NFR-007 | P1 | P4 | 3 дн. | SG-06, SG-09 |
| SG-08 | Собрать размеченные работы. Качество и время проверки измерить отдельно для вычислений и доказательств, а расход рассчитать по журналу вызовов | US-004, NFR-008–NFR-012 | P1 | P3 | 3 дн. | SG-04, SG-05 |
| SG-09 | Образ из Dockerfile запускается через Compose с постоянным томом. Тесты выполняются в GitHub Actions, а миграции проходят на чистой БД. Для проверки восстановления команда создаёт резервные копии БД и файлов. На КТ-3 сборку доставляют на ВМ и проверяют после запуска | US-003, US-006, NFR-004, NFR-005, NFR-006, NFR-007 | P0 | P4 | 4 дн. | Начать параллельно и подключить сдачу после SG-03 |
| SG-10 | Попросить преподавателя подготовить пробное задание и замерить время ручной проверки. В отчёте отделить наблюдения от гипотез | BR-001–BR-003, US-001, US-004, US-005 | P1 | P1 | 2 дн. | Нужен тестовый набор. Для пилота требуется SG-06 |
| SG-11 | Реализовать API создания предмета и вступления по коду с миграциями предметов и участия. Список предметов и форму создания подключает Алина. Код преподаватель копирует со страницы предмета | US-007, US-002, NFR-003, NFR-007 | P0 | P1 | 2 дн. | Согласовать ID пользователя с Алиной |

Предварительная оценка MVP составляет 36 человеко-дней. На КТ-2 в SG-04 испытали два PDF. Через HTTP в SG-06 и SG-07 проверили, что преподаватель утверждает балл за одну задачу, а студент не видит черновик. По SG-09 готовы миграция SQLite, запуск через Compose и базовый CI. Доставка новой версии на ВМ и восстановление из копии запланированы на следующие точки.
