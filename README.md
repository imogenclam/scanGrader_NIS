# Scan Grader

Scan Grader помогает преподавателю проверять письменные работы по математике. В MVP студент сможет вступить в предмет по коду и сдать решение в PDF. ИИ сверит работу с закрытым эталоном преподавателя в формате `.tex` и предложит балл с пояснением по каждой задаче. Итог утвердит преподаватель.

## Технический сценарий КТ-2

В учебной работе одна задача с максимумом в 1 балл. В SQLite уже записан черновик на 0,5 балла. До утверждения студент видит только номер работы и её статус. Распознавание PDF проверено отдельно. [Истории US-005 и US-006](docs/requirements/stories.md#us-005-исправить-и-утвердить-результат) · [Учебные данные](src/storage/migrations/001_init.sql) · [Опыт с PDF](docs/quality/baseline.md#распознавание-скана)

Если преподаватель ставит 1,2 балла, сервер возвращает HTTP 400 и оставляет работу на проверке. Когда преподаватель утверждает 0,7 балла с комментарием «Арифметическая ошибка», студент видит этот результат даже после перезапуска контейнера. [Обработчик API](src/api/http.go) · [Интеграционные тесты](tests/review_test.go)

### Запуск и пример запроса

Для запуска нужен Docker Compose 2.24 или новее. На учебной ВМ предусмотрены 2 vCPU и 4 ГБ памяти. Выполните команду из корня проекта. При первом запуске миграция создаст учебную работу и учётные записи преподавателя и студента. [Compose](compose.yaml)

```sh
docker compose up --build -d --wait
```

По умолчанию сервис отвечает на `http://127.0.0.1:8080`. Если порт занят, скопируйте `.env.example` в `.env` и задайте свободный порт в `SG_PORT`. Готовность сервиса показывает `GET /healthz`. [Настройки](.env.example)

Запустите пример с Python 3.12. Скрипт получит учебные токены через Compose и проверит ответы для обеих ролей. При повторном запуске он прочитает уже утверждённую оценку. Ключи внешних моделей для примера не нужны. [Запросы и ответы](docs/api/README.md) · [Пример оценки](docs/api/examples/approve.json)

```sh
python3 tests/demo_api.py
```

В Windows используйте `py -3 tests/demo_api.py`. Чтобы остановить контейнер и сохранить базу, выполните `docker compose stop`.

Тесты Go запускаются командой `go test -count=1 ./...` с Go 1.26.11. Для полной проверки выполните `bash ci/check.sh` из чистой копии репозитория. Если команда `python3` недоступна, задайте путь к Python в `PYTHON_BIN`. Скрипт запишет результаты в `test-results/`. [Скрипт CI](ci/check.sh) · [Результаты](docs/quality/baseline.md)

## Команда

Проектом руководит Сергей Андреевич Овчинников. Схему базы данных участники разрабатывают совместно.

| Код | Участник | Работа в MVP | Ожидаемый результат |
| --- | --- | --- | --- |
| P1 | Галимов Артур Тагирович | Паспорт проекта и требования. Серверная часть Classroom | Преподаватель создаёт предмет и публикует задание. Студент вступает по коду |
| P2 | Лисянская Алина Рифовна | Дизайн и фронтенд Classroom. Личный кабинет с разграничением доступа и безопасным хранением учётных данных | Студент регистрируется и входит в кабинет, где может изменить профиль. Через страницу предмета он сдаёт работу |
| P3 | Артур Галимов | Приём и сжатие PDF, ядро ИИ-проверки. Экран преподавателя с исходным PDF и черновиком | Преподаватель правит баллы по задачам и утверждает итог. Если ИИ-проверка прервётся, работу можно проверить вручную |
| P4 | Алина Лисянская | Страница результата для студента. Ручное и автоматическое тестирование, GitHub Actions и запуск на ВМ | Студент видит свою оценку после публикации. Тесты проверяют его путь от регистрации до результата |
