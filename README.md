# Scan Grader

Scan Grader предназначен для проверки письменных работ по математике. В полном сценарии преподаватель создаёт предмет и передаёт студентам код приглашения. Студент вступает в предмет и сдаёт решение в PDF. Сервис должен сверить скан с закрытым эталоном в формате `.tex` и предложить балл с пояснением по каждой задаче. Итоговую оценку утверждает преподаватель.

## Технический сценарий КТ-2

На КТ-1 команда описала, кто вправе менять оценку и когда студент увидит результат. В техническом каркасе эти правила реализованы для одной учебной работы. При первом запуске в базе появляется задача с максимумом в один балл и черновиком на 0,5 балла. Черновик задан в учебных данных. Распознавание скана проверяется в отдельном эксперименте. [Истории US-005 и US-006](docs/requirements/stories.md#us-005-исправить-и-утвердить-результат) · [Результаты эксперимента](docs/quality/baseline.md#распознавание-скана)

Пока работа ожидает проверки, студент видит только её номер и статус. Преподаватель может утвердить 0,7 балла с комментарием «Арифметическая ошибка». После этого студент получает балл и пояснение, а результат сохраняется в SQLite после перезапуска. Если до утверждения преподаватель попытается выставить 1,2 балла, сервер вернёт HTTP 400 и работа останется на проверке. [Обработчик API](src/api/http.go) · [Миграция SQLite](src/storage/migrations/001_init.sql) · [Интеграционные тесты](tests/review_test.go)

### Запуск и пример запроса

Из корня проекта запустите Docker Compose с поддержкой `--wait` (версия 2.24 или новее). Плановый профиль учебной ВМ составляет 2 vCPU и 4 ГБ памяти. Сервис доступен на `http://127.0.0.1:8080`. Если порт занят, скопируйте `.env.example` в `.env` и задайте свободный порт в `SG_PORT`. При первом запуске сервис применит миграцию и создаст учебную сдачу с двумя ролями. Ключи внешних моделей для этого не нужны. [Настройки](.env.example) · [Compose](compose.yaml)

```sh
docker compose up --build -d --wait
```

Готовность проверяется запросом `GET /healthz`. Для демонстрации запустите скрипт с Python 3.12. Он сам определит локальный порт и получит токены учебных ролей через Compose. На новой базе скрипт проверяет ошибочный запрос, утверждает балл и читает его от имени студента. При повторном запуске уже утверждённый результат сохраняется. [Примеры запросов и ответов](docs/api/README.md) · [Данные для утверждения](docs/api/examples/approve.json)

```sh
python3 tests/demo_api.py
```

В Windows можно использовать `py -3 tests/demo_api.py`. Для остановки с сохранением данных выполните `docker compose stop`. Команда `go test -count=1 ./...` с Go 1.26.11 запускает тесты на временной базе. Для полной проверки из чистой копии Git выполните `bash ci/check.sh` с теми же Docker, Go и Python. Если команда `python3` недоступна, путь к интерпретатору можно задать через `PYTHON_BIN`. Отчёты появятся в `test-results/`. [Скрипт CI](ci/check.sh) · [Протокол локальных проверок](docs/quality/baseline.md)

## Команда

Проект выполняется под руководством Овчинникова Сергея Андреевича. В таблицах приведено распределение работ по полному MVP.

| Участник | Зона ответственности | Ожидаемый результат |
| --- | --- | --- |
| Галимов Артур Тагирович | Отвечает за серверную часть Classroom и ядро ИИ-проверки. Реализует экран преподавателя для просмотра PDF и оценивания. В базе данных ведёт предметы, задания и результаты проверки | Преподаватель публикует задание в предмете. После сдачи открывает PDF рядом с черновиком по задачам и утверждает итог. При сбое может проверить работу вручную |
| Лисянская Алина Рифовна | Отвечает за регистрацию, вход и разграничение доступа в личном кабинете. Ведёт профили и отвечает за безопасное хранение учётных данных. Проектирует интерфейс сервиса и реализует страницы Classroom, личного кабинета и результата. Тестирует пользовательские сценарии и настраивает автоматические проверки | Студент может зарегистрироваться, войти и отредактировать профиль. Из Classroom он открывает задание и после проверки видит свою оценку. Автоматические тесты проверяют этот путь |

| Код | Ответственный | Граница работы |
| --- | --- | --- |
| P1 | Артур | Паспорт и карта требований. Предметы, участие по коду и публикация заданий на сервере |
| P2 | Алина | Дизайн интерфейса и фронтенд. Регистрация, вход и личный кабинет. Страницы Classroom, через которые студент вступает в предмет и сдаёт работу |
| P3 | Артур | Приём PDF на сервере, сжатие и ИИ-проверка. Экран с PDF и черновиком, где преподаватель правит и утверждает оценку |
| P4 | Алина | Страница утверждённого результата для студента. Тестирование сервиса вручную и с помощью автоматических проверок. GitHub Actions и запуск на ВМ |

Схему базы данных Артур и Алина разрабатывают совместно.
