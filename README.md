# Scan Grader

Scan Grader помогает преподавателям публиковать домашние задания по математике и проверять работы с помощью ИИ. Преподаватель создаёт предмет в Classroom и передаёт студентам код приглашения. После вступления студент открывает задание и сдаёт работу в PDF. Сервис сверяет решение на скане с закрытым эталоном в формате `.tex` и предлагает балл с пояснением по каждой задаче. Итоговую оценку утверждает преподаватель.

## Запуск через Docker Compose

Из корня проекта выполните на машине с Docker Engine и Docker Compose 2.24 или новее

```sh
docker compose up -d --build
docker compose exec app scangrader -init-teacher
```

Откройте [Scan Grader](http://127.0.0.1:8080). При первом создании аккаунта команда выводит логин `teacher` и случайный пароль. Для проверки готовности выполните `curl --fail http://127.0.0.1:8080/healthz`. Остановить сервис с сохранением тома можно командой `docker compose stop`.

Пользователь также может зарегистрироваться через интерфейс и подтвердить почту шестизначным кодом. По умолчанию сервис складывает учебные письма в закрытый каталог `/data/mail` контейнера, при запуске на Windows — в `data/mail`. Код содержится в файле `.eml` с адресом получателя. На общем стенде подключается SMTP. Для запуска ручного оценивания ключи OCR и модели не требуются. [Настройки и технический сценарий](docs/implementation.md)

## Разработка интерфейса

Код интерфейса находится в `web/src`. Чтобы работать над дизайном КТ-2, склонируйте ветку с приложением и запустите сервер из корня проекта. Для этого варианта нужны Docker Compose и Node.js 22.18 или новее.

```sh
git clone --branch cp2/technical-skeleton https://github.com/imogenclam/scanGrader_NIS.git
cd scanGrader_NIS
docker compose up -d --build
docker compose exec app scangrader -init-teacher
npm --prefix web ci
npm --prefix web run dev -- --host 127.0.0.1
```

Откройте адрес, который напечатает Vite, обычно `http://127.0.0.1:5173`. Войдите как `teacher` с паролем, который контейнер выводит при первом создании аккаунта. Vite передаёт запросы API на порт 8080 и обновляет страницу, когда вы сохраняете изменения в React или CSS.

Цвета и шрифты заданы в [стилях](web/src/styles.css). Общая навигация находится в [компонентах страницы](web/src/components/layout/). Страницы [Classroom](web/src/classroom/) охватывают публикацию и сдачу задания, а [экран проверки](web/src/review/Work.tsx) показывает PDF и оценку. Формы входа и регистрации находятся в [модуле аккаунтов](web/src/features/auth/).

Для отдельного PR с дизайном создайте свою ветку от `cp2/technical-skeleton`. При открытии PR укажите `cp2/technical-skeleton` как целевую ветку. Так изменения интерфейса можно проверить вместе с сервером до сдачи КТ-2.

## Запуск на Windows

В локальной поставке для Windows x64 откройте `start.cmd`, сохраните пароль при первом запуске и перейдите по указанному в окне адресу. База данных и закрытые файлы остаются в каталоге `data` рядом со скриптом. Для остановки нажмите Ctrl+C. В поставке исходного кода исполняемый файл можно собрать командой `go build -o bin/ScanGrader.exe ./cmd/server` после сборки интерфейса.

## Сборка из исходников

Для сборки нужны Node.js 22.18 или новее, npm и Go с инструментарием 1.26.11. Версии зависимостей зафиксированы в файлах проекта. Команды выполняются из корня репозитория. Сначала собирается React, поскольку его ресурсы встраиваются в Go-бинарник.

```sh
npm --prefix web ci
npm --prefix web test
npm --prefix web run build
go vet ./...
go test ./...
go build -o scangrader ./cmd/server
node tests/contract/classroom.mjs ./scangrader
```

Последняя команда использует временную БД, сама создаёт учебные аккаунты, публикует задание, проверяет отказ в доступе и выдачу результата за PDF. На Windows можно передать путь `bin/ScanGrader.exe`. Для полноценного запуска сервера из исходников выполните `go run ./cmd/server -init-teacher`, затем `go run ./cmd/server`. Для рендеринга страниц при вызове OCR вне контейнера нужен Ghostscript или `pdftoppm`.

## Контрольные точки

### Результат КТ-2

В браузерной проверке студент сдал PDF, после чего преподаватель открыл исходный файл и утвердил 0,7 балла за решение. Студент увидел эту оценку вместе с комментарием преподавателя. Когда из второй вкладки отправили другой PDF, ссылка открыла первоначально принятую работу. Сценарий сравнивает содержимое открытого файла с оригиналом. [Проверка в Chrome](web/tests/classroom.mjs)

Правило оценивания также проверено через REST API. При максимуме в один балл преподаватель попробовал выставить два и получил HTTP 400. Затем сервер принял допустимую оценку. Студенту, который запросил закрытый эталон, сервер вернул HTTP 403. [Вызовы и ожидаемые ответы](tests/contract/classroom.mjs) · [Порядок запуска](docs/api/README.md#исполняемый-пример)

Отдельный эксперимент прослеживает путь от страницы PDF до черновика оценки. Рендерер прочитал синтетический скан. Адаптер распознавания отправил изображение страницы и получил контрольный текст `2 + 2 = 4`. Следующий запрос содержал этот текст и эталон преподавателя. По заданному ответу модели сервис сформировал черновик в один балл. Ответы внешних API в этом эксперименте фиксированы. Проверка качества на размеченных работах предусмотрена планом испытаний. [Эксперимент со сканом](internal/ai/scan_test.go) · [Локальные результаты](docs/quality/baseline.md) · [Методика испытаний](docs/quality/strategy.md)

Для одной учебной ВМ команда выбрала SQLite и закрытый том для PDF. При выборе PostgreSQL и объектного хранилища пришлось бы обслуживать ещё две службы и отдельно восстанавливать их после сбоя. Условия пересмотра решения описаны в [ADR-002](docs/adr/ADR-002-storage.md).
