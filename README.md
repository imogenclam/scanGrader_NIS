# Scan Grader

Scan Grader помогает преподавателю проверять сканы домашних работ по математике. В Classroom преподаватель создаёт предмет и передаёт студентам код. Студент вводит код, чтобы открыть предмет, а затем выбирает опубликованное задание и загружает готовый PDF. ИИ-проверка читает решение на скане и сверяет его с закрытым эталоном в формате `.tex`, чтобы предложить балл с пояснением по каждой задаче. Итог утверждает преподаватель.

Репозиторий проекта находится на GitHub. [scanGrader_NIS](https://github.com/imogenclam/scanGrader_NIS)

## Технический подход

На КТ-1 команда фиксирует проектный подход. На КТ-2 она проверит его на сквозном техническом сценарии.

| Область | Проектное решение |
| --- | --- |
| Интерфейс | Веб-интерфейс обращается к серверу через REST API по HTTPS. Регламент допускает REST, а контракт для него команда оформит в OpenAPI на КТ-2 |
| Стек | Для веб-интерфейса предлагаем React, а для сервера Go. Для MVP предлагаем SQLite. Подходит один экземпляр приложения с локальным файлом БД. Команда проверит параллельные сдачи и запись оценок на учебной нагрузке |
| Стенд | На одной учебной ВМ Docker Compose запускает контейнер Go, который отдаёт собранный интерфейс React и REST API. На КТ-2 команда подготовит `Dockerfile`, `compose.yaml`, `.env.example` и миграции. GitHub Actions собирает и проверяет версию. Начиная с КТ-3 автоматическая доставка запускает проверенную сборку на ВМ и проверяет доступность сервиса |
| Хранение | SQLite хранит учётные записи и предметы. Участие связывает студента с предметом, а задание принадлежит предмету. К сдаче привязаны метаданные файла, версия эталона и оценка. Файл БД вместе с PDF и `.tex` лежит на закрытом постоянном томе. Для одновременного чтения и записи команда проверит режим WAL. Запись в БД идёт короткими транзакциями, а внешние вызовы проходят вне них. Команда проверит восстановление БД и файлов из согласованной резервной копии |
| ИИ-проверка | Сервис обрабатывает скан и готовит предварительную оценку по эталону. На КТ-2 команда выберет схему обработки и поставщика после прогона на тестовых работах. Прогон позволит оценить качество, время и стоимость. В CI используют фикстуры |

## Разбор на защите КТ-1

1. За 5 минут объясните, у каких пользователей возникает проблема и как её проверить. Расскажите, какую пользу должен дать MVP и где проходят его границы. Покажите план замера времени проверки.
2. За 3 минуты пройдите по карте от создания предмета до утверждения итога. Преподаватель создаёт предмет по US-007 и публикует задание по US-001. Студент вступает по коду (US-002), а затем сдаёт PDF (US-003). После появления черновика (US-004) преподаватель утверждает результат (US-005). Из НФТ разберите NFR-001, NFR-003 и NFR-008.
3. Оставьте 2 минуты на вопросы. Если потребуется пояснить формат результата, используйте пример из US-004.
